## 3. What three problems does Git & GitHub solve?

1. **Version history:** Git tracks every change, so you can see what changed, when, and who changed it, and roll back if something breaks.
2. **Collaboration:** Many people can work on the same project at the same time using branches and merging, without overwriting each other's work.
3. **Backup and sharing:** GitHub stores your code online, so it is safe if your computer fails, and others can view, use, or contribute to it.

## 4. What happens when you `fork` a repository?

Forking creates your own copy of someone else's repository under your GitHub account. The original stays untouched. You can change your copy freely and, if you want, propose those changes back to the original through a pull request.

## 5. What happens when you clone a repository?

Cloning downloads a full copy of a repository (all files and the complete history) from GitHub to your computer, using `git clone <url>`. It also sets up a link called `origin` pointing back to the remote repo.

## 6. What is a Pull Request?

A pull request (PR) is a request to merge changes from one branch (or fork) into another. It lets teammates review the code, comment on it, and approve it before it becomes part of the main project.
